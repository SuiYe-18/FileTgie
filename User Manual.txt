1. What is FileTgie / 简介
==============================================================

FileTgie is a lightweight, read-only, zero-dependency command-line
tool for file statistics and simple searching. It is written in pure
C, and the same source code builds both a Windows executable and a
Linux executable. It runs in a black console window; everything is
done through command-line arguments.

FileTgie 是一个轻量、只读、零依赖的命令行文件统计与查找工具。纯 C
编写，同一套源码同时编译出 Windows 与 Linux 可执行文件。它在黑窗口
（控制台）中运行，全部通过命令行参数执行。

Its core philosophy is "step by step, slowly" (一步一步慢慢来): each
command does one small, clear and predictable job. Its core promise
is clean statistics and read-only safety: it never modifies, deletes
or moves any user file, so there is no danger of an accidental
operation.

核心理念是「一步一步慢慢来」：每个命令只做一件小事，结果清晰、可预期。
核心承诺是统计清明、只读安全：不修改、不删除、不移动任何用户文件，
因此不会出现误操作错误。

Four interface languages are available: Chinese cn, English en,
Japanese ja, Russian ru, switched with a command-line option.

界面提供四种语言：中文 cn、英文 en、日文 ja、俄文 ru，用参数切换。

2. Read-only Safety / 只读安全承诺
==============================================================

Inspection commands only call reading interfaces: directory
enumeration, stat (file metadata), and fread (reading bytes). They
never modify, delete or move your files; they only inspect them.

检查类命令只调用读取接口：目录枚举、stat（文件元信息）、fread（读取
字节），不修改、不删除、不移动用户文件，只做查看。

During normal use the only FileTgie writes are its own filetgie.log next
to the executable: log prints it, and dellog deletes this log only.
The explicit update command upgrades FileTgie itself: on Windows it
launches the bundled FileTgieUpdater.exe, which checks GitHub and the
website and starts the newer silent installer. During an overwrite, the
previous program files are moved to a disabled .old backup folder before
the new files take over; on Linux it prints manual source-build steps
and never replaces the binary. The optional reminder command only creates
or removes the FileTgieReminder user-level scheduled task; it does not
scan, modify or delete your files.

常规使用中，FileTgie 只写入可执行文件旁自身的 filetgie.log：log 查看，
dellog 只删除这一份自身日志。显式 update 命令只更新 FileTgie 自身：
Windows 启动同目录 FileTgieUpdater.exe，由它检查 GitHub 与官网并启动
新版静默安装；覆盖时旧程序文件先移动到禁用的 .old 备份文件夹，再由新文件
接管；Linux 只打印源码构建的手动升级步骤，不替换二进制。可选的 reminder
命令只创建或删除 FileTgieReminder 用户级计划任务，不扫描、修改或删除你的文件。

3. Installation / 安装
==============================================================

Portable edition / 绿色便携包

The portable package contains FileTgie.exe, FileTgieUpdater.exe,
README.md, User Manual.txt, LICENSE, COPYING and examples\demo.ftg.
It is fully portable:
it does not write to the registry and does not install into Program
Files. Unzip it and use it; to uninstall, simply delete the folder.

便携包含 FileTgie.exe、FileTgieUpdater.exe、README.md、User Manual.txt、
LICENSE、COPYING 与 examples\demo.ftg。工具完全便携：不写注册表、不写入 Program Files。解压即用，
删除文件夹即完成卸载。

The portable edition does not require administrator rights.

便携版不需要管理员权限。

Windows installer / Windows 安装包

The installer registers App Paths and system PATH under Program Files.
It detects an installed FileTgie, App Paths registration, or leftover
files after a non-official deletion. The overwrite option is checked by
default; uncheck it and choose another directory to preserve the old
copy. On overwrite, previous FileTgie.exe, FileTgieUpdater.exe and
documentation files are moved to .old next to the installation folder.
The registry, PATH and shortcuts always point to the new files in the
root folder; .old is a disabled backup and is never launched.
Installation needs administrator rights for registry and PATH changes.

安装包在 Program Files 中部署并注册 App Paths、系统 PATH。它会检测已
安装的 FileTgie、App Paths 注册，或非官方删除后的残留文件。“覆盖安装”默认
勾选；保留旧副本时请取消勾选并另选目录。覆盖时，旧的 FileTgie.exe、
FileTgieUpdater.exe 与文档会移动到安装目录旁的 .old 备份文件夹；注册表、
PATH 与快捷方式始终指向根目录新文件，.old 只是禁用备份，不会被启动。注册与
PATH 修改需要管理员权限。

Linux build / Linux 构建

v0.5.3 adds the `help-<command>` per-command detail help; the platform-
independent .ftg script layer from v0.5.1 is unchanged. The Linux-compatible
source code remains available for `make`, after which run
`./FileTgie --lang en help` and optionally copy FileTgie into a directory in
PATH. Inspection commands need no installer, administrator rights or network;
checkupdate uses curl to query GitHub. The older verified x86_64 glibc
prebuilt tarball remains the unchanged v0.4.0 Release package; build v0.5.3
from source on Linux.

v0.5.3 新增 `help-<命令>` 单命令详细帮助；v0.5.1 的平台无关 .ftg 脚本层保持不变。
兼容 Linux 的源码仍可执行 `make` 构建，然后运行 `./FileTgie --lang en help`，也可按需把
FileTgie 复制到 PATH 目录。检查类命令不需要安装程序、管理员权限或网络；checkupdate
通过 curl 查询 GitHub。较早验证过的 x86_64 glibc 预编译包保持为未改动的 v0.4.0 Release
包；Linux 请从源码构建 v0.5.3。

Building from source / 从源码构建

Windows (MinGW gcc), in the project root directory:

  gcc -O2 -Wall -Wextra -o FileTgie.exe src\main.c src\commands.c src\port.c src\util.c src\i18n.c src\update.c -lwinhttp -lshell32
  gcc -O2 -Wall -Wextra -o FileTgieUpdater.exe src\updater_main.c -lwinhttp -lshell32

Or just run build.bat. The build expects zero warnings with
-O2 -Wall -Wextra and produces FileTgie.exe plus the Windows-only
FileTgieUpdater.exe; Linux make does not build the updater.

Windows（MinGW gcc）在项目根目录执行上述命令，或直接运行 build.bat。
构建要求 -O2 -Wall -Wextra 零警告，产出 FileTgie.exe 与 Windows 专用
FileTgieUpdater.exe；Linux make 不构建更新器。

Linux (gcc / clang):

  make

This produces FileTgie. All source code lives in src/ and uses only
the C standard library and native platform APIs, with no third-party
dependencies.

Linux（gcc / clang）执行 make，产出 FileTgie。源码全部位于 src/，
仅使用 C 标准库与平台原生 API，无第三方依赖。

Linux toolchain support / Linux 工具链支持

The Linux source tree was previously verified on GCC 11.4.0 (Ubuntu 22.04,
x86_64, glibc) with -O2 -Wall -Wextra clean. The same tree also builds clean
under -std=c99, -std=gnu99, -std=c11, -std=gnu11 and -std=gnu17, so it does
not require C11-only syntax. A C99-capable GCC 5+ on modern glibc is expected
to build from source; older versions were not tested one by one. musl/Alpine is
not guaranteed; use make on the target distribution. Clang is not verified.

Linux 源码树曾在 GCC 11.4.0（Ubuntu 22.04，x86_64，glibc）以
-O2 -Wall -Wextra 零警告验证；同一源码在 -std=c99、-std=gnu99、-std=c11、
-std=gnu11、-std=gnu17 下也均零警告，不依赖 C11 专属语法。现代 glibc 上具备
C99 能力的 GCC 5+ 预期可从源码构建，更低版本未逐版本实测。不保证
musl/Alpine；请在目标发行版执行 make。Clang 本版未验证。

4. Quick Start / 快速上手
==============================================================

General syntax / 通用语法:

  FileTgie [--lang cn|en|ja|ru] [--exclude <glob>] [--exclude-ext <ext>] <command> [args...]

Language option / 语言选项

--lang (also written -lang or -l; supports = notation such as
--lang=en or -l=ja; language codes are case-insensitive) may appear
before or after the command. An unrecognized language code prints a
localized warning and falls back to the default cn, then continues
running.

--lang（也可写 -lang、-l，支持 --lang=en、-l=ja 等号写法，语言码
大小写不敏感）可放在命令前或命令后。无法识别的语言码会给出本地化
警告并回退默认 cn，程序继续运行。

Exclusion options / 排除选项

--exclude <glob> (or --exclude=<glob>) skips files whose basename
matches the wildcard (* ?) during directory traversal; matching is
case-insensitive on the basename; the option may be repeated.

--exclude <通配符>（或 --exclude=<通配符>）：目录遍历时跳过 basename
匹配通配符（* ?）的文件；basename 匹配大小写不敏感；可重复使用。

--exclude-ext <ext> (or --exclude-ext=<ext>) skips files of the given
extension; a leading dot is optional (.c and c are the same), matching
is case-insensitive, and the option may be repeated.

--exclude-ext <扩展名>（或 --exclude-ext=<扩展名>）：跳过指定扩展名的
文件；带不带前导点等价（.c 与 c 相同），大小写不敏感；可重复。

Both exclusion options only affect traversal commands. Commands that
take an explicitly named single file (such as lines and hash) are
not affected.

两个排除参数只作用于遍历型命令；显式指定单个文件的命令（如
lines、hash）不受影响。

Help and exit codes / 帮助与退出码

Running FileTgie with no arguments, or entering help, prints the full
command table and exits with code 0. Success returns rc=0; usage
errors, path-not-found errors and argument errors return rc=1.

不带任何参数或输入 help 会显示完整命令表，退出码 0。成功返回
rc=0；用法错误、路径未找到、参数错误返回 rc=1。

Simple .ftg scripts / 简单 .ftg 脚本

A .ftg file is a plain-text sequence of existing FileTgie commands. It is
not a programming language: there are no loops, if conditions, calculations,
pipes or background jobs. Write one command per line.

.ftg 文件是由已有 FileTgie 命令组成的纯文本顺序清单。它不是编程语言：没有循环、
条件判断、数学计算、管道或后台任务。一行写一个命令。

Example / 示例:

  # comment / 注释
  set folder = "D:\Docs"
  echo Inspecting $folder
  exists $folder
  count $folder
  linesdir $folder
  lang en
  version
  exit 0

Run it with either form / 两种运行方式:

  FileTgie run demo.ftg
  FileTgie demo.ftg

Symbols / 符号: # starts a comment; = saves a variable; $name or ${name}
substitutes a variable; "..." or '...' keeps spaces in a path or phrase;
echo prints text; lang changes only this script's language; exit stops early.

符号：# 开头为注释；= 保存变量；$名称 或 ${名称} 替换变量；"..." 或 '...'
保留路径或文字中的空格；echo 输出文字；lang 只切换本脚本语言；exit 提前结束。

6. Languages / 语言切换
==============================================================

Four language codes are supported: cn (Chinese), en (English),
ja (Japanese), ru (Russian). Use --lang, -lang or -l before or after
the command; the = notation and letter case do not matter.

支持四种语言码：cn（中文）、en（英文）、ja（日文）、ru（俄文）。
在命令前或命令后使用 --lang、-lang 或 -l；等号写法与字母大小写

  FileTgie -lang ja lines ./a.txt

An unrecognized language code prints a localized warning, falls back
to cn, and keeps running.

无法识别的语言码会打印本地化警告，回退到 cn 后继续运行。

7. Log / 运行日志
==============================================================

FileTgie keeps its own run log in filetgie.log next to the executable.
Every invocation appends one record: local timestamp, language code,
command, arguments and exit code.

FileTgie 在可执行文件旁的 filetgie.log 中保存自身运行日志。每次调用
都会追加一条记录：本地时间戳、语言码、命令、参数、退出码。

Use log to print the log and dellog to clear (delete) it. The log path
is computed inside the program, so it does not depend on the current
working directory.

用 log 查看日志，用 dellog 清空（删除）日志。日志路径在程序内统一
计算，不依赖当前工作目录。

checkupdate is a manual, read-only network check: it queries GitHub,
compares the local version with the latest release and reports status.
update performs the same check first; on Windows it launches the bundled
FileTgieUpdater.exe, which checks GitHub and the official website,
downloads the newer installer, and starts the silent overwrite install.
Linux only prints manual upgrade commands. The program never checks on
startup; reminder only runs when the user explicitly enables a task.

checkupdate 是手动、只读的网络检查：查询 GitHub，比较本地版本与最新
Release 并报告状态。update 先执行同样检查；Windows 随后启动同目录的
FileTgieUpdater.exe，由它同时检查 GitHub 与官网、下载新版安装包并启动
静默覆盖安装；Linux 只打印手动升级命令。程序启动时不会自动检查；只有用户显式
开启 reminder 后，计划任务才会按设定时间运行。

The installer detects an installed FileTgie, App Paths registration, or
leftover files after a non-official deletion. The "overwrite installation"
option is checked by default; uncheck it and choose another directory if
you want to keep the old copy untouched. On overwrite, old program files
are moved to a disabled .old backup folder; the active registry, PATH and
shortcuts continue to point only to the new root-folder files.

安装包会检测已安装的 FileTgie、App Paths 注册，或非官方删除后留下的
残留文件。“覆盖安装”默认勾选；若要保留旧副本，请取消勾选并另选目录。覆盖时，
旧程序文件会移入禁用的 .old 备份文件夹；生效的注册表、PATH 与快捷方式始终只
指向根目录新文件。


==============================================================
8. Size Units / 大小单位
==============================================================

FileTgie uses the 1024 binary standard: 1 KB = 1024 B and
1 MB = 1024 KB, advancing B -> KB -> MB -> GB by 1024. A size that
has not reached the next unit stays in the current unit.

FileTgie 采用 1024 二进制标准：1 KB = 1024 B，1 MB = 1024 KB，
按 1024 从 B -> KB -> MB -> GB 进位；未到上一级单位时保持当前单位。

The size, stat, du and dirdiff commands also print the exact byte
count alongside the human-readable size.

size、stat、du、dirdiff 命令会在人类可读大小之外同时给出精确字节数。

9. FAQ / 常见问题
==============================================================

Q: Does the portable edition need administrator rights?
A: No. It runs as a normal user; it writes nothing except its own
filetgie.log next to the executable.

问：便携版需要管理员权限吗？
答：不需要。普通用户即可运行；除可执行文件旁自身的 filetgie.log 外
不写任何位置。

Q: Why won't FileTgie modify my files?
A: By design it is read-only: it only enumerates, stats and reads. It
never modifies, deletes or moves user files.

问：为什么 FileTgie 不会修改我的文件？
答：这是设计上的只读承诺：只枚举、stat、读取，绝不修改、删除、移动
用户文件。

Q: Can fd be used together with FileTgie?
A: Yes, as a separate external companion. fd quickly locates candidate
files and can run batch delete/move operations through its own -x/-X
options; those actions belong to fd or the shell. FileTgie does not
call or bundle fd, and it only performs read-only statistics, checksums,
encoding detection and comparison.

问：fd 可以和 FileTgie 一起使用吗？
答：可以，把它当作独立的外部搭配工具。fd 负责快速定位候选文件，并可
通过自己的 -x/-X 选项执行批量删除、移动；这些操作属于 fd 或 shell。
FileTgie 不调用、不打包 fd，只做只读统计、校验、编码检测与对比。

Q: What happens with an unknown language code, an unknown option or
wrong arguments?
A: An unknown -/-- token (such as --foo or -x) is reported as an
unknown option and points to help, rc=1. Missing option values or
empty = values (such as --lang=) report a missing/empty option value,
rc=1. An invalid language code warns and falls back to cn. Fixed-
parameter commands reject extra trailing arguments; optional N values
use defaults when omitted; numeric thresholds are strictly parsed
(empty, non-numeric, negative, NaN/Inf and overflow all fail with a
localized error, rc=1) instead of silently becoming 0.

问：遇到未知语言码、未知选项或错误参数会怎样？
答：不认识的 -/-- 开头 token（如 --foo、-x）按"未知选项"报错并指向
help，rc=1；选项缺跟随值或 = 后留空（如 --lang=）报"缺少选项值 /
值不能为空"，rc=1；无效语言码打印警告后回退 cn。固定参数命令拒绝
多余尾随参数；可选 N 缺省时用默认值；数值阈值严格解析（空串、
非数字、负数、NaN/Inf、溢出均报本地化错误，rc=1），绝不静默当成 0。

Q: What does an empty directory, empty file or no-match result print?
A: An empty directory is a legal input. When a traversal command finds
no file or no match, it prints one localized "no matches found" line
with rc=0. A 0-byte file reports line/word/character/longest-line/
blank/CJK counts as 0 or "none" and returns normally.

问：空目录、空文件、无匹配时输出什么？
答：空目录是合法输入。遍历命令无文件或无匹配时打印一行本地化
"未找到匹配项"，rc=0；0 字节文件的行数/词/字符/最长行/空行/CJK
等输出 0 或"无"，正常返回。

Q: The terminal says "FileTgie is not recognized as a command".
A: Type the full path to FileTgie.exe (for example
D:\FileTgie\FileTgie.exe) to run it. If you installed the setup
edition, add its install directory to the PATH environment variable
so FileTgie can be typed directly.

问：终端提示"FileTgie 不是可识别的命令"怎么办？
答：使用 FileTgie.exe 的完整路径运行（例如 D:\FileTgie\FileTgie.exe）。
若使用安装版，可把安装目录加入 PATH 环境变量，之后即可直接输入
FileTgie。
